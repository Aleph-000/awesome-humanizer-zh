# awesome-humanizer-zh

AI 生成的中文常常没有明显的语法错误，读起来却带着翻译腔或刻意加工的痕迹。句子可能频繁依靠转折制造语气，用“高级感”“宿命感”代替具体分析，也可能为了显得简洁有力，把单字动词放进中文里少见的搭配。

`awesome-humanizer-zh` 收集了实际写作中遇到的这些问题，并把每次修改积累成可以直接使用的提示词。它关注现代汉语的自然表达，也处理段落组织、人物介绍、引用方式和作品赏析。完整内容见 [SKILL.md](./SKILL.md)。

## 主要内容

- **词语搭配**：检查“取、停、推、挂、记、接”等单字动词，以及“还、很、也”等单字副词在当前句子中是否自然。`x住`、`x一下`和陌生化的动词组合也在检查范围内。例如，“把观点推得更具体”“孤零零地挂在歌词上”“这个名字很值得记一下”都需要结合原意改成完整、常见的中文说法。
- **评价与描写**：“歌词很厚”“处理很漂亮”“这句话很好”只写出了态度。评价应当说明相关的歌词、画面、声音、人物动作或结构，再把判断的理由讲清楚。“空间感”“故事感”“宿命感”等词可以偶尔使用，不能代替对具体内容的观察。
- **句式与段落**：减少为了强调语气安排的否定和转折，直接写出需要表达的内容。抽象评价、承上启下和意义总结没有必要单独成段；事实、例子与分析放在一起，读者更容易看清它们之间的关系。
- **介绍与引用**：陌生人物、歌词、采访和制作背景第一次出现时，先交代人物身份、事情发生的场景和必要背景。引用应当自然地进入叙述，并保留足以独立理解的完整内容，避免突然抛出半句话或一个陌生名字。
- **作品赏析**：选择真正影响理解的歌词、画面和声音细节，说明作品怎样呈现人物与情境。制作故事、歌手经历和历史资料可以穿插，篇幅始终服从当前作品。介绍音乐制作时，重点放在实际听到的变化，不用乐器名称和制作术语堆满段落。

## 规则的整理过程

每条规则都来自人工写作和修改。遇到生硬搭配、空泛评价、突兀引用或失去中心的段落时，先记录原句，再写下具体问题和修改要求，随后根据新的生成结果继续补充。SKILL.md 保留了大量反例，使用者可以看见规则针对的表达，也能据此判断相似句子。

本项目特别处理中文里常见的细小问题。单字需要放在具体搭配中判断，它与前后词语共同决定一句话读起来是否自然。清楚的事实和完整的分析已经能够帮助读者理解内容，不必为每个细节另写一句意义总结。相关规则始终从中文原句和实际修改出发。

## 与 Humanizer-zh 的关系

[Humanizer-zh](https://github.com/op7418/Humanizer-zh) 参考英文原版并进行了中文翻译。

`awesome-humanizer-zh` 的内容由作者独立编写，编写过程中未参考 `Humanizer-zh` 或其他已有文件。现有规则来自中文写作中的手工标注、提示词调整和反复纠正。

## 使用方式

复制 [SKILL.md](./SKILL.md) 的完整内容或当前任务需要的部分，将其加入模型提示词或自定义指令。生成文章时，可以与写作要求一同提供；修改已有内容时，可以附上原文，让模型按照其中的反例和规则逐段检查。
