# awesome-humanizer-zh

`awesome-humanizer-zh` 是一份为中文写作整理的语言风格提示词。它帮助模型检查生硬的词语搭配、空泛的评价、机械的段落过渡，以及不符合中文阅读习惯的信息顺序。

不少生成内容语法完整，单独看每句话似乎都说得通，连在一起却像翻译腔或刻意加工过的文案。常见问题包括用“高级感”“宿命感”代替具体分析，把“取、停、推、挂、记、接”等单字硬塞进不合适的搭配，以及反复用“不是……而是……”营造冲突。本文档把实际写作中遇到的问题逐条记录下来，提供可以直接加入提示词的修改要求。

## 为什么需要中文专用规则

中文表达有自己的词语搭配、句子节奏和叙述顺序。一个词放在字典里意思正确，进入具体句子后仍可能显得突兀。比如“取得很漂亮”“把观点推得更具体”“孤零零地挂在歌词上”，读者能够猜出意思，却很少有人在自然交谈或成熟文章中这样组织语言。

单字词语尤其容易造成这类问题。“取、停、推、挂、记、接”原本都有正常用法，问题出现在模型为了追求短促或力度，把它们放进缺少惯用搭配的句子里。“还、很、也”等单字副词同样需要结合语境使用，不能依靠删减字数制造所谓的简洁。项目要求模型保留完整、常见的现代汉语表达，让动词、修饰语和宾语之间的关系自然成立。

## 主要处理的问题

1. **生硬的词语搭配**：检查单字动词、单字副词和陌生化组合，优先选择日常中文里稳定、完整的说法。规则结合上下文判断具体用法，保留这些字在自然搭配中的正常用法。
2. **缺少依据的评价**：“歌词很厚”“处理很漂亮”“这句话很好”只交代了作者的态度。修改时需要指出相关的歌词、画面、声音、动作或结构，再说明这些细节怎样支持评价。
3. **抽象词和“××感”**：“空间感”“故事感”“宿命感”可以概括印象，连续使用会让具体内容消失。文章应当交代声音远近如何变化、人物做了什么、画面怎样安排，或者歌词使用了哪些意象。
4. **机械的对立和过渡**：“不是……而是……”“没有……反而……”经常被用来制造并不存在的冲突。能够直接表达的观点应当直接写出，承上启下词只在逻辑确实需要时出现。
5. **不自然的内容顺序**：陌生人物、歌词、采访和历史事件第一次出现时，先说明人物身份、发生场景和必要背景，再进入引用与分析。人物故事、制作经历和历史资料都围绕当前主题展开，避免作品赏析逐渐变成人物生平或资料汇编。

## 这套规则怎样修改文字

下面是一段虚构的音乐赏析，用来展示修改思路。示例中的歌词情节和编曲细节只为说明方法，不对应真实作品。

修改前：

> 这段歌词很有故事感，编曲也很高级。它不是在写普通的离别，而是在写一种强烈的宿命感。

修改后：

> 第二段主歌写主人公收起桌上的两套餐具，门外的脚步声逐渐消失。鼓点在唱到这里时停下，贴近人声的钢琴保留了房间里的安静。生活中的动作和突然空下来的声音共同表现离别，读者能够从具体场景里理解人物为什么舍不得对方。

原段落使用“故事感”“高级”和“宿命感”概括判断，却没有提供可以理解这些判断的内容。改写先交代歌词中的动作，再说明编曲发生了什么变化，最后分析两组细节如何共同表现离别。评价有了清楚的依据，读者也能沿着作者的观察理解作品。

## 内容来源

[Humanizer-zh](https://github.com/op7418/Humanizer-zh) 以英文原版为基础进行了中文翻译。

`awesome-humanizer-zh` 由作者独立编写，编写过程中未参考 `Humanizer-zh` 或其他已有文件。每条规则都来自中文写作中的人工标注、提示词调整和多次纠正，内容集中在中文语境下的措辞、句式、段落组织与作品赏析。

## 使用方式

打开 [SKILL.md](./SKILL.md)，复制完整内容或当前任务需要的章节，将其加入模型的提示词或自定义指令。生成新内容时，可以提前说明需要遵守这些写作习惯；修改已有文章时，可以同时提供原文，并要求模型逐段检查具体问题。
